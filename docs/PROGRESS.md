## Как читать и обновлять

**Статусы:**

| Значок | Что значит |
|---|---|
| ✅ | Готово: написано, запускается, проверено вживую |
| 🔧 | В работе прямо сейчас |
| ⏳ | Не начато, но срок ещё не горит |
| 🚨 | Под угрозой: сроки или блокер, нужна помощь команды |
| ⛔ | Заблокировано: ждём чужую задачу или ответ организаторов |
| 🗑 | Решили не делать (с причиной) |

**Правила:**

1. У каждой задачи есть **ID** (`G1-03`, `J-05`...). В коммитах и PR ссылайтесь на ID:
   `G1-03: оркестратор, ретраи с бэкоффом`. Так по истории видно, кто что закрыл.
2. Приоритеты из плана: **P0** — без этого решения нет, **P1** — заметно добавляет
   баллов, **P2** — если останется время. P0 чужого участника важнее своего P1.
3. Меняете статус на 🚨 или ⛔ — сразу пишете строку в разделе «Блокеры».
4. Что-то решили не делать — ставите 🗑 и пишете причину, не удаляете строку.
   Через три дня никто не помнит, почему этого нет.
5. Поменяли общий контракт (БД, API, формат инсайта) — пишете в «Решения» и
   предупреждаете остальных: контракты заморожены, молча их менять нельзя.

## Журнал по дням

### Д2 — 21.10.2026

**Go #1, безопасность AI-контура (`G1-18` ✅).** Описание всех механизмов
и их места в архитектуре — [SECURITY.md](SECURITY.md). Реализовано и проверено:

- **Своя роль БД на каждый сервис** с минимальными правами (миграция 00004, пароли —
  job `db-roles` из окружения). Проверено запросами: `svc_gateway` получает
  `permission denied` на `companies` и `news` — у единственного сервиса с ключом
  к моделям нет доступа к данным клиентов; `svc_ml` только читает; `svc_api` не
  может менять статусы пайплайна. `go-ingest` под своей ролью отработал все операции
  без единой ошибки прав.
- **Идентификаторы компаний и физлиц маскируются в логах** на уровне логгера:
  `U_67` → `U_***`, `F_64255` → `F_***`, включая тексты ошибок.

**Важно Go #2, Java, Python:** сервисы теперь ходят в базу под `svc_api`, `svc_agent`,
`svc_ml`. Новая таблица в вашем диапазоне миграций → в той же миграции `GRANT` своей
роли, пример — в [README миграций](../internal/infra/db/postgres/migrations/README.md).

Попутно нашёлся и починен подвох для демо: на Windows `curl -d 'кириллица'` портит
текст ещё до сервера (curl.exe получает аргументы в ANSI-кодировке), и вброшенная
новость приходит из символов-заменителей. Смоук и пример в README теперь шлют тело
через stdin. Браузер и сервисы шлют UTF-8 нормально — проблема только в ручных
вызовах curl из Git Bash.

**Go #1, конвейер поехал (`G1-14` ✅, `G1-15` ✅).** Оркестратор раз в 10 с
прогоняет этапы: дедуп → обогащение → склейка в сюжеты → подбор компаний (go-api)
→ разбор (java-agent). Что они должны отдать — [PIPELINE_CONTRACTS.md](PIPELINE_CONTRACTS.md).

На живом потоке (937 новостей):

- **662 отсеяны как шум, 275 идут дальше** — около 70% потока не дойдёт до моделей.
  Отсев проверен глазами: уходят спорт, происшествия, некрологи, политика без экономики;
  остаются санкции, нефть и газ, экспорт дизеля, дивиденды, банкротства, логистика.
- Склейка в сюжеты строгая: 270 сюжетов, 5 из них из двух источников — все пять
  действительно одно событие, ложных склеек ноль. Перепечатки с переформулированным
  заголовком fallback не ловит — это задача семантической склейки питониста.
- **Конвейер упирается в go-api:** эндпоинта подбора компаний пока нет, оркестратор
  это видит и ждёт, не сжигая попытки (в `job_attempts` — ноль). 270 сюжетов пойдут
  дальше, как только Go #2 его поднимет.

Словарь fallback калибровали на реальных ложных срабатываниях, каждое — в тесте:
«оптоволокно» ловилось как «оптовая торговля», «сектор Газа» — как газ, «Автомобилист»

## Решения, которые уже приняты

1. **Монорепозиторий, один Go-модуль, три бинаря** (`go-ingest`, `llm-gateway`, `go-api`):
   общие domain, миграции и инфраструктура БД, никакого дублирования схемы.
2. **LLM-Gateway — отдельный сервис, а не библиотека.** Ключ есть только у него,
   поэтому Java и Python физически не могут обойти бюджет и аудит.
3. **Кодогенерацию из OpenAPI не используем** (четыре стека, восемь дней):
   спека пишется руками и держится в синхроне с хендлерами. Расхождение — баг.
4. **Деньги считаем в копейках (`int64`)**, включая стоимость вызовов моделей.
5. **Размерность эмбеддинга — 768.** Меняется только миграцией и только по согласию.
6. **Справочники нормализованы таблицами** (`pipeline_statuses`, `attribution_types`),
   а не `CHECK`/`ENUM`: бизнес-правила живут в коде, БД держит целостность.
7. **Идемпотентность пайплайна** — уникальным индексом `(story_id, company_id, model_version)`
   на `insights`, а не проверками в коде.
8. **Источники не удаляем, а выключаем** флагом `enabled`: история парсинга
   остаётся воспроизводимой.
9. **Два Go-разработчика живут в одном модуле, а не в двух.** Общие `domain`,
   миграции и слой БД — то, ради чего монорепозиторий и заводился; разделение
   на модули заставило бы дублировать схему и сломало бы «единый запуск» из
   чеклиста сдачи. Вместо этого: карта владения файлами (CLAUDE.md §13),
   диапазоны номеров миграций по владельцам, ветка на сервис и PR в `main`,
   `.github/CODEOWNERS` для автоназначения ревьюера.
10. **Новый статус `FILTERED`** (миграция 00003) — штатный выход из воронки:
    новость-шум или сюжет, не релевантный ни одной компании. Это не сбой, поэтому
    не `FAILED`, и оркестратор не подбирает такие записи на каждом тике.
11. **py-ml отвечает, а в базу пишет оркестратор.** У перехода `DEDUPED → ENRICHED`
    один владелец, а питонисту не нужен доступ к базе на запись — только эндпоинт.
    go-api и java-agent, наоборот, пишут свои таблицы сами (`story_company_scores`,
    `insights`): это их данные, оркестратор только двигает статус.
12. **«Сосед не готов» — не сбой.** 501/404/недоступен — этап ждёт следующего тика
    без попыток; остальные ошибки — ретраи с бэкоффом и dead letters. Поэтому
    заглушки коллег не засоряют `dead_letters`, пока эндпоинты не реализованы.
13. **Строки захватываются `FOR NO KEY UPDATE SKIP LOCKED`, не `FOR UPDATE`.**
    Java и go-api вставляют строки со ссылкой на `stories`; проверка внешнего ключа
    берёт `KEY SHARE`, и `FOR UPDATE` заблокировал бы их до конца нашей транзакции,
    пока мы ждём их же ответа.
